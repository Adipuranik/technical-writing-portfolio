# IoT Sensor Data Format Documentation

## Overview

This document describes the structure and format of sensor data generated by an ESP32-based IoT temperature monitoring system.

The documentation provides field definitions, data types, example payloads, and XML representation to help developers and support teams understand how sensor data is structured.

## Data Fields

| Field | Data Type | Description | Example |
|---|---|---|---|
| device_id | String | Unique identifier of the IoT device | ESP32-001 |
| temperature | Decimal | Temperature measured in degrees Celsius | 28.6 |
| humidity | Decimal | Relative humidity percentage | 62.0 |
| status | String | Current operational status of the device | active |
| timestamp | DateTime | Date and time when the reading was recorded | 2026-08-20T10:30:00 |

## XML Data Format

The following XML example represents a sensor reading generated by the device:

```xml
<?xml version="1.0" encoding="UTF-8"?>

<sensorReading>
    <deviceId>ESP32-001</deviceId>
    <temperature unit="Celsius">28.6</temperature>
    <humidity unit="percent">62.0</humidity>
    <status>active</status>
    <timestamp>2026-08-20T10:30:00</timestamp>
</sensorReading>
```

## XML Structure

### `sensorReading`

The root element that contains all information associated with one sensor reading.

### `deviceId`

Identifies the ESP32 device that generated the reading.

Example:

```xml
<deviceId>ESP32-001</deviceId>
```

### `temperature`

Stores the measured temperature. The `unit` attribute identifies the measurement unit.

```xml
<temperature unit="Celsius">28.6</temperature>
```

### `humidity`

Stores the measured relative humidity.

```xml
<humidity unit="percent">62.0</humidity>
```

### `status`

Indicates the current operating status of the device.

```xml
<status>active</status>
```

### `timestamp`

Records when the sensor reading was generated.

```xml
<timestamp>2026-08-20T10:30:00</timestamp>
```

## XML Elements and Attributes

This example demonstrates two fundamental XML concepts:

**Elements** contain structured data:

```xml
<deviceId>ESP32-001</deviceId>
```

**Attributes** provide additional information about an element:

```xml
<temperature unit="Celsius">28.6</temperature>
```

Here, `temperature` is the element and `unit` is an attribute.

## Example: Multiple Sensor Readings

Multiple readings can be represented under a common root element:

```xml
<?xml version="1.0" encoding="UTF-8"?>

<sensorReadings>

    <sensorReading>
        <deviceId>ESP32-001</deviceId>
        <temperature unit="Celsius">28.6</temperature>
        <humidity unit="percent">62.0</humidity>
        <status>active</status>
        <timestamp>2026-08-20T10:30:00</timestamp>
    </sensorReading>

    <sensorReading>
        <deviceId>ESP32-001</deviceId>
        <temperature unit="Celsius">29.1</temperature>
        <humidity unit="percent">61.5</humidity>
        <status>active</status>
        <timestamp>2026-08-20T10:35:00</timestamp>
    </sensorReading>

</sensorReadings>
```

## Validation Considerations

When processing the XML data:

- Each document should contain one root element.
- Every opening XML tag must have a corresponding closing tag.
- Element names must use consistent capitalization.
- Temperature and humidity values should contain valid numerical data.
- Each sensor reading should contain a device identifier and timestamp.
